# Precision allocation and evidence limits

This table describes the isolated study implementation and the experiments run by 2026-11-01. It is not a new precision policy for ordinary Robust reception. The benchmark's current reference modes are strict FP32 (TF32 disabled) and FP64. Mixed/storage precision modes remain diagnostic experiments unless their full sensitivity, ranking, admission and runtime evidence is resolved.

| Stage | Current representation and arithmetic | Evidence, value of extra precision, and remaining gap |
|---|---|---|
| Waveform, channel, oscillator and front-end simulation | The C++ sampled path uses the shared channel/front-end implementation and double-precision scalar/model state; exported sufficient statistics are complex128 with float64 real fields. The sampled basis export is complex64. Integer sample counts/offsets accompany the simulation timeline. | This preserves long paths, shaping, tails and oscillator state in the simulator. The sampled basis export deliberately reduces template storage to complex64; template-storage error is measured separately from arithmetic. No hardware DAC/ADC is implied by these software paths. |
| Sample clock and long-time coordinates | C++ simulation uses integer sample coordinates/counts plus double-precision physical time and phase/model parameters; the export records uint64 sample intervals and double-valued metadata. | Hour and day-length continuity are covered by sampled simulator paths, not by a systematic precision sweep of all timestamp, carrier-phase and sample-clock arithmetic. Real device clock/phase performance remains unmeasured. |
| Correlations, energies and Gram construction | Sampled export computes its accumulated statistics in the C++ `Complex` path and stores Gram/correlation matrices as complex128. GPU harness receives that fixed exported design; strict FP32 casts the working tensors to complex64, while FP64 retains complex128. | Independent FP64 input/reference paths and paired score comparisons are available. Lower precision can perturb small differences and nearly rank-deficient designs; the current representative case set is not an exhaustive ill-conditioned-channel qualification. |
| Basis rank and QR/MGS | The sampled precision probe loads the exported complex64 basis, converts those stored values to complex128, then uses FP64 modified Gram-Schmidt with the recorded rank tolerance (default `1e-6`). Quantized-storage modes re-score quantized basis representations; these are distinct from quantizing observations. | This is FP64 arithmetic on complex64-exported templates, not an independently generated FP64 waveform/template reference; it cannot restore bits lost at export. Rank, likelihood/ranking, misses and wrong admissions are recorded per mode. A 2-candidate fixed-window bank is only a numerical diagnostic; it does not establish rank stability across the full acquisition family. A general SVD policy was not qualified. |
| Gaussian channel covariance preparation | `PreparedGaussianDesign` converts fixed Grams to CPU complex128, checks Hermitian/PSD conditions, then uses FP64 eigendecomposition, Cholesky, posterior covariance and log determinants. It caches those design-only values. | On the synthetic 929-block B32 profile, CPU FP64 design preparation took 0.158–0.174 s across observed runs. Resident gain was 3.78× in FP32 and 4.06× in FP64; complete preparation, transfer and verification gains were only 1.64× and 1.73×. Warm CPU single-use was about 0.95×, so this is useful when design work is reused. Runtime FP32/complex64 remains a finite-precision variant requiring paired validation. This separate Gaussian-state algorithm does not cover nonlinear quantization or clipping. |
| Finite phase/frequency state transitions | Transition probabilities, oscillator grid and kernels are prepared in FP64; the declared bulk likelihood executes in FP32 or FP64. Strict CUDA FP32 rejects TF32 or non-highest matmul precision. The optimized stencil also uses ordinary FP32/FP64 products and accumulation, without tensor-core reduced-input modes. | FP64 reference and strict FP32 were compared on matched inputs. The finite Markov oscillator is exact only for its declared discrete model; continuous colored phase/frequency mismatch remains. No lower-precision oscillator-state policy has been qualified. |
| Emissions and per-observation likelihood | Bulk correlations/Grams and state updates use complex64/FP32 or complex128/FP64. The likelihood implementation disallows lower-precision matrix multiplication. Long accumulated log evidence is FP64. | On the profiled B1 paired H0/H1 inference, full-bulk graph FP64 took 0.704 s versus 0.202 s for strict FP32. This is a 3.49× inference-time cost in that case, not an end-to-end time or a sensitivity result. FP64 evidence accumulation protects long sums and weak likelihood margins without making all bulk operations FP64; tail calibration remains unresolved. |
| Posterior normalization and long reductions | State weights, emission logits, and their per-update maximum are computed in the selected FP32/FP64 bulk dtype. Exponentiated weights are summed in FP64; the running log-evidence increment adds the bulk maximum after conversion to FP64 to the FP64 logarithm of that sum. State renormalization (`predicted / predicted.sum`) uses the bulk dtype. The optional two-level reducer uses FP64 accumulation and storage at both sum levels. | A graph trace measured a 1.348 ms FP64 conversion/copy across 32 profile updates (about 42 μs/update), not per update and not the whole inference. The two-level reducer was about 1.15× faster than graph inference in paired full-hour tests in both execution orders, with maximum score difference 4.3e-14 and no observed decisions changed. These reduction-order results do not establish tail-equivalence for every long duration. |
| Noise estimation and whitening | The representative sufficient-statistic path uses declared Gaussian noise variance; it does not estimate an arbitrary colored noise covariance. Gram whitening/factorization in the cached Gaussian method is prepared in CPU complex128. | Unknown covariance, impulsive interference and quantization can violate the Gaussian projection shortcut. Such cases require actual sampled observations through the nonlinear processing, with fresh matched validation. |
| Detection threshold and duration planning | Threshold and duration arithmetic is evaluated in host double precision in the study tooling. Null calibration may use exact-model likelihood identities or an explicitly scoped empirical fixed-family method. | Neither method alone qualifies the operational maximum over timing, frequency, epoch, channel model, duration and repeated attempts. The default `99% / 1e-4 per 24 h` target and relaxed `90% / 1% per 12 h` target remain unproven by the available small campaigns. No zero-event extrapolation is accepted as operational evidence. |
| ADC/DAC quantization | Physical path options place transmitter quantization before propagation and receiver quantization after modeled analog effects, noise/gain and filtering. Nominal bit depth, ENOB, full scale, gain, dither and clipping are distinct parameters. The ADC bound's sample rounding is then scored with ideal arithmetic for its stated fixed-family model. | In paired fixed-path screens, 16-bit operation with high headroom produced small projection changes; lower full scale and interference caused overload/clipping. A deterministic Cauchy-Schwarz rounding-error bound is available only for unclipped finite rank-one known-window templates and ideal arithmetic. Measured perturbations are empirical checks, not a floating-point certificate or operational tail proof. |

## Precision decisions

The evidence supports keeping strict FP32 as an explicitly tested throughput mode and FP64 as the numerical comparison mode for the isolated finite-state GPU path. The tested strict FP32 mode does not silently enable TF32. FP64 CPU preparation is retained for the cached Gaussian covariance route; its cost and transfer/amortization assumptions must be included when comparing complete jobs. FP16/BF16 storage and product attempts, real decompositions, TF32 requests, and padded FP8/INT8 tensor experiments are diagnostic only. Some requested modes are unsupported or have unverified dispatch/accumulation, and must be identified as such in their result JSON.

The 0.1, 0.25, 0.5 and 1 dB sensitivity-loss budgets are **unresolved**. No paired confidence interval currently establishes a crossing at these budgets for the operational receiver. Quantized observations, clipping, AGC, dither, colored/interfering noise and converter overload must be evaluated from the actual sample-domain path; a linear Gaussian projection result is not interchangeable with it. No experimental precision setting changes the default receiver.
