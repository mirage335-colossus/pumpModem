# Requirements and implementation coverage

Version **001_00** is feature complete for its defined scope. All features listed
as implemented below are available. The sole planned addition is automatic
radio-frequency tuning to find suitable HF shortwave ionospheric propagation
frequencies, as an alternative to Automatic Link Establishment (ALE) and
Frequency Hopping Spread Spectrum (FHSS); that tuning is not yet implemented.

Operators maintain written procedures for carrier frequencies, listening
schedules, and whether `0` or `1` represents status or distress on each agreed
frequency. These procedures define interpretation and response for the existing
exact-bit transport.

Feature completeness is separate from performance and hardware qualification.
Audio peers need matching waveform settings. Automatic profiles use binary
pattern transport;
nonempty text of up to 16 source bytes uses the fixed short dictionary, while
longer text and all attachments use fixed 128-byte intervals. Existing keyfiles
remain usable. These paths and per-bit pending reception are
[development requirements](development.md).
[Test execution results](validation.md) distinguish measured results from design
and source-level checks.

Unless a row explicitly names Fast or Legacy, the modem/transport descriptions
below describe Robust (regular) mode. Its compatibility requirements remain
unchanged.

| Requirement | Implemented behavior / current boundary |
| --- | --- |
| Independent Fast mode | The Modem dropdown selects Fast text/file transfer with live waveform, waterfall and constellation plots. Independent QAM/LDPC, acoustic OFDM and classic APSK profiles use fixed 2,048-coded-bit intervals, bounded source preparation and XZ compression. Expected SNR and Symbol rate select local waveform/coding settings; both peers use matching profiles. Encryption is optional: AES-256-CBC/HMAC with a selected key, public checksums otherwise. Decompression and attachment interpretation wait for physical completion. Fast has no LPI claim. See [Fast format and validation limits](fast-mode.md). |
| Independent Legacy mode | The Modem dropdown selects a simplex text console for BPSK31, BPSK125 and Olivia-4/2k, with live received/transmitted text, a retained send draft, editable audio carrier, receive squelch and waterfall. Settings and the regression-only sampled channel are independent of Robust and Fast. Text is unauthenticated; noisy reception can contain errors. See [Legacy Modem](legacy-modem.md). |
| Portable compiled modem | C++20 CLI and default FLTK GUI share the transfer/streaming service and OpenSSL 3. Optional Rev uses C++23 and the shared controller/bitmap boundary; its Linux software-OpenGL profile is tested. Linux ALSA is dynamically optional; Windows uses WinMM. No Python or Tk runtime dependency. See [Rev boundaries](rev-backend.md); Windows hardware validation remains separate. |
| Offline installation transfer | CMake/CPack collects compiled executables and native libraries. Bundled FLTK, OpenSSL and release C++ runtimes default to static linking. Moving a release needs no interpreter or package download. OS/CPU/glibc compatibility limits are in [offline-installation.md](offline-installation.md). |
| Portable CI binaries | GitHub Actions builds and tests Linux and MSVC Windows archives, with static CRT/OpenSSL, relocation, checksum and GUI checks. Linux CI targets glibc 2.35 and checks downloaded copies on Ubuntu 22.04/24.04, rejecting GTK/GLib dependencies. Hosted results require an actual successful workflow run; local newer-glibc builds do not inherit that baseline. |
| Text, screenshots and files | Text compose, restricted received-text clipboard copy, exact raw-bit copy, and binary file or saved-screenshot attachments. Received text stays in the ticker; only files/screenshots appear in the explicit-save list. Screenshots are ordinary image files saved with the operating system's tools. Exact completed payload bytes remain available for explicit file saving. See the [received-text contract](development.md#restrict-received-text-before-presentation). |
| Interface isolation | PCM or analog audio only, with OS-default device and optional override. Received content is displayed under the restricted character policy and files are saved only by explicit operator action. Hardware isolation is external. |
| Audio controls | All three GUIs select Left mono, Right mono or Stereo and playback-only TX volume from 0.01% to 175% (default 100%); levels above 100% can clip. Device selection uses the existing audio backend. Linux supports shared or explicitly exclusive access; Windows WinMM remains shared. Simulation and WAV exports retain their existing mono waveform and level. |
| 256 MiB receive content | Bounded application cache with local reception identities and eviction. DSP has an independent ceiling. Fixed interval/marker/RS scratch drains into quota-limited source memory; post-end output has its own content quota. Reception uses no temporary files or disk cache. Neither number is a total process RSS cap. |
| Large keyfile and pad | Production 128 MiB random header wraps an authenticated collection of 1..128 named complete five-purpose keysets. GUI opens, generates/saves in the background and shows the loaded file's folder. New files use exclusive creation and select the first named key. Legacy keyfiles load as Default. Optional large pad support remains in CLI. No physical-erasure guarantee. |
| Compose convenience fields | GUI Callsign and Grid seed an editable `CQ CQ CQ DE <callsign> GRID <grid>. Please reply. ` greeting when Message is cleared; absent fields omit their corresponding clause, and both absent omit the greeting. Values are carried only in visible message text. Starting a text transmission clears to the current convenience text and enables Previous message - click to paste for exact message restoration, including its repeatable identifier. Editing the recalled message generates a fresh identifier. |
| Repeatable messages | GUI Repeatable is ordinary visible `REPEATABLE-XXXXXXXX ` source text with local compose policy; it adds no modem flag or received command. Callsign/grid greetings also remain source text. |
| Raw bits and fixed byte streams | Nonempty text of up to 16 source bytes uses the fixed short dictionary, with exact endpoints and no markers, padding, FEC or MAC. Explicit raw bits bypass dictionary encoding and preserve leading zeros and non-byte lengths. Text longer than 16 bytes and all attachments use marker + 128 coded bytes with fixed local FEC/source/key profiles. Fixed local geometry determines framing; received lengths never control modem boundaries, allocation or completion. Public intervals have no digest or authentication. Attachments use a bounded source prefix after physical end and source decoding. See [protocol](protocol.md). |
| Settling and fixed intervals | Binary pattern transport is the sole waveform. Rounded hardware settling mixes selected private streams in separate preamble positions and supplies no acquisition condition. An exact three-second independent noise tail suppresses weaker echoes without an end marker. Markers precede every fixed interval; all bits consume cipher positions. |
| Automatic compression | Text of up to 16 bytes always uses the fixed short dictionary; explicit bit drafts bypass encoding. Eligible unmarked receptions decode only after physical end into at most 16 bytes, without validation/authentication claims. Interval-coded sources in the locally selected compressed mode always emit one raw LZMA2 stream with a fixed 4 MiB dictionary and final zero fill shorter than one data area. Original-size fields remain removed. Decompression runs only after physical end, with separate input, scratch and output caps. Uncompressed interval mode uses fixed validity/byte cells. |
| Cipher streams | AES-256-CTR with HKDF purpose separation and canonical symbol-start epoch/ordinal addresses. Selected non-tone keys enable private patterns. Only encrypted intervals carry a fixed 32-byte HMAC-SHA256, protected by RS and bound to domain/profile/address/data. Exact raw bits have no MAC. Schedule reuse and replay limitations remain. |
| Tone policy | Tone modes force encryption, Scrambler and DSSS off; the GUI clears and disables key selection and the transfer/CLI/live APIs normalize stale keys away. Tone modes are unencrypted communications or experiment modes, with no LPI claim. |
| Time, key and target search | Receive searches only the selected rate, carrier and pattern/tone mode. The selected carrier and internal clock participate in pattern-length planning and confidence checks. A separate comma-separated target C/N0 field accepts up to 16 finite values in -200..200 dB-Hz; invalid input resets the whole list to `32`, and equivalent profiles share one search. Loaded keys, whole-second epochs (default ±6 seconds), finite carrier offsets and timing hypotheses are subject to aggregate workspace admission. Resource-limited coverage is reported. Acquisition depends on the signal falling within those finite configured hypotheses. |
| Local targets and channel assumptions | Separate short/raw and long/file TX targets select pattern duration. RX target profiles can be edited independently; changing either TX target resets the list to both effective targets. Simulation power, attenuation, noise and oscillator settings determine the modeled channel independently of those design targets. The Link planner previews a target until the operator explicitly applies it. |
| Transmit policy | One active GUI TX; common hardware separation must cover the complete-symbol absence rule and waveform tails in all modes. Automatically timed output schedules the first payload symbol on a whole second. Simulation supplies actual trailing samples and cannot inject a transmitter end into RX. Independent processes/hosts are not coordinated. |
| Continuous tuning noise | Transmit noise produces continuous noise at the selected carrier, rate, routing and playback level until stopped, with fresh temporary cryptographic streams on each start. It preserves the message draft and selected key. Simulation previews the same generator; observed power and interference depend on the channel. See [tuning noise](crypto.md#continuous-tuning-noise). |
| Phase and amplitude modulation | All pattern chips use bounded circular Gaussian-derived I/Q values. Private chips have key-dependent amplitude and phase; public templates repeat a deterministic complex row each symbol. The two bit alternatives differ in internal transitions. Tone uses two carrier offsets. No APSK constellation lock is used. |
| Automatic weak-signal duration | Bandwidth and target C/N0 choose binary-pattern integration with the existing modeled 18 dB symbol-energy target. The floor is 16 nominal chips at in-band SNR >=30 dB, 32 at >=24 dB, otherwise 64; automatic tones retain 64. Shortened automatic profiles require whole chips at the actual sample clock. Compact orthogonal private bins reserve at least 32 chips; other profiles outside the 256-sample exact-fit range retain 64. Longer integrations advance the full private stream beyond 16,384 chips. Forced shorter profiles remain selectable but may be marked below the applicable confidence floor. No measured sensitivity or false-alarm guarantee follows from this planner. |
| Long-symbol memory behavior | TX generates bounded PCM chunks using fixed seekable code caches. RX normally uses bounded FFT/baseband history; symbols exceeding that workspace can use a scalar correlator with an explicit half-chip clock-start window and finite frequency/rate bank. Equivalent subsecond phases share references; distinct symbol addresses use compact running fits. State scales with this hypothesis count, not airtime or buffered keystream duration. Multiple rates/epochs increase memory and CPU; coverage remains subject to admission and live real-time feasibility is not established for large banks. See [search-state bounds](pattern-constellation.md#streaming-long-symbol-correlation). |
| Missing symbols and message end | Timed unknown slots preserve cipher/byte positions and become RS erasures. Iterative search scores complete symbols; the first failed symbol suffices when its duration is at least six seconds, otherwise consecutive failed durations must cover six seconds. No partial-symbol preemption. EOF, cancellation, quotas, codec ends and FEC/MAC outcomes never complete a stream. |
| Post-completion recovery | Bounded recovery of damaged leading markers and an additional resumable hard-bit search run only after physical completion. The additional search defaults to five wall-clock minutes, uses up to the available CPU cores and retains at most 65,536 hard-bit slots separately from the diagnostic prefix. Missing-bit assignments and fixed alignment hypotheses use the existing RS/HMAC and independent alignment-evidence rules; only a unique reconstruction exposes source content. Budget exhaustion or cancellation leaves work unfinished. See [recovery scope](protocol.md#exhaustive-hard-bit-recovery). |
| Link planning and estimates | Link planner compares bit duration, modeled receive probability and receiver compute cost for selected power, path loss, noise and oscillator assumptions. Applying a planner target is explicit. CLI estimate and analysis tools expose the same models, with coverage limits, sampling uncertainty and an ideal Shannon-Hartley capacity reference. LPI relative observation is an advisory model; it is neither a safe traffic limit nor hardware qualification. See [Link planner](link-planner.md) and [simulation estimates](simulation-estimates.md). |
| Planner and throughput bounds | Automatic transport carries one bit per pattern. Capacity optimality, minimum workable pattern length and calibrated weak-signal sensitivity are not established. Timing adjustments and rate/frequency hypotheses have finite configured coverage; reception depends on the signal remaining within it. |
| Rate, carrier and spectrum | Nominal 0.01 Hz..30 MHz rate planning uses internal `Fs=ceil(max(64,4B,4fc))`, independently of hardware. The GUI defaults to Rate `3.6 kHz` and Carrier `1.5 kHz`; other GUI rates retain the previous `max(1500,0.75B)` carrier recommendation, and carrier can be overridden. The CLI defaults to Rate 1,200 Hz with carrier `max(1500,0.75B)` Hz. The GUI defaults to short/raw target C/N0 32 dB-Hz, long/file target 55 dB-Hz and RX targets `32, 55`; CLI defaults to 32 dB-Hz. At least 16 complete chip times enables default 25% RRC shaping with a 16-chip span; the new GUI default has 1,800 chips/s and ideal support 375–2,625 Hz including rolloff. Shorter patterns and tone retain rectangular pulses and the conservative nominal passband guard. A circular 0.992-radius limiter bounds overlapping peaks; a tested private capture lost 0.083 dB mean power relative to linear shaping. Cipher streams, chip mapping and synchronization rules are unchanged. Both peers must match rate, carrier and `Config::pulse_shaping`; no negotiation marker is sent. Audio uses bounded band-limited rate conversion. The connected audio device's physical passband limits actual operation; RF spectral compliance requires intended-device measurements. See [pulse shaping](modem.md#pulse-shaping). |
| Few-bit status | Pattern transport sends and blindly recovers exact raw bits, including leading zeros and non-byte lengths, without supplied boundaries or bit counts. Three bits occupy three payload symbols plus rounded settling and, for shaped profiles, eight chip times of filter tail at each burst edge; these tails carry no extra bits. An additional three-second independent noise tail suppresses weaker echoes. Raw confidence does not authenticate identity or prove a physical long-distance link budget. Operator-written procedures assign the meaning of each bit and frequency and specify listening schedules and responses. |
| Multi-signal reception | Bounded pattern candidates and chains can report bursts within the finite frequency/timing/key/epoch bank. Continuous capture releases old waveform history. Coverage is confined to that configured bank; admission limits can exclude hypotheses. |
| Provisional text and completed bits | Reception displays every newly accepted raw symbol on the next progress poll, with no byte or chunk-size minimum. Only the six-second whole-symbol absence rule completes a reception, including raw messages. Corrected source areas remain internal until the physical end event; no compressed preview or pre-end source decode. Completed bytes support safe display and explicit copy/save. Unresolved intervals make reconstruction incomplete. |
| Signal reception quality | Pattern evidence, unknown slots, RS corrections and keyed interval authentication are separate. Public streams have no digest/authentication claim. Pre-FEC accuracy covers observed bits; missing bits are reported separately. RS repair counts include data, keyed HMAC and parity, including zero-valued erasures. |
| Diagnostics | Continuous sample windows preserve carrier phase; waveform, spectrum and waterfall remain bounded. Constellation plots distinguish measured receiver input from up to 2,048 retained transmitted chip I/Q values; plot geometry does not control acquisition. Unseen displaced points are counted. Slow-rate formatting remains; overloaded-device performance is not guaranteed. |
| Simulation | Independent free-running receiver processes actual PCM with seeded fractional start timing/carrier phase, AWGN, default 100 ppm relative crystal error and 0.5 degrees/sqrt(second) Wiener phase diffusion. Idle noise continues and TX boundaries do not reset RX. Memory is bounded; work scales with sample count. Presets use -174 dBm/Hz plus 10 dB noise figure, normalized to Fs/2. Ideal-clock overrides retain unsynchronized startup. |
| Simulation presentation | Sampled reception includes actual trailing absence under the same full-symbol rule. Presentation replay does not replace physical completion, invoke pre-end decompression or reveal prepared source contents. Stop interrupts undelivered presentation without inventing stream end. |
| Replay storage | Diagnostic previews, event queues and retained source content have separate byte quotas. Corrected compressed areas remain in capped RAM storage until completion. Quota exhaustion marks content incomplete while bounded physical search may continue. |
| Physical channel effects | Sampled simulation and batch PCM apply startup timing/phase, delay, frequency shift, clock resampling and phase noise. Pattern fits determine acquisition success; finite local timing adjustments or explicit rate hypotheses cover only their implemented range. This model covers only the listed channel effects. Long integrations can fail with the default crystal error/phase noise even when memory fits. |
| QR Level L | Vendored encoder, UTF-8 ECI, up to 500 Unicode scalars; compose preview and SVG/PBM CLI output. Independent decoding history is recorded in validation results. |
| Pattern/scrambler constellation | Modem flow shows two one-bit codeword rows with duration-weighted distances and energy-normalized timing comparisons. Long symbols show at most a 16,384-chip illustrative prefix. Private illustrations reset to public example keys and epoch, never actual streams. Tone distances are chip-center approximations. No diagram calibrates reception confidence. |
| Pattern acquisition | Soft pattern-versus-noise fits alone admit symbols and refine timing; neither APSK residual, preamble, checksum nor source validity locks the automatic receiver. Shaped templates retain the independent raw sample/bin noise accounting and actual template energy/Gram terms; neighbor tails and crest-limiter error are model mismatch. Strong individual symbols can establish a burst; weaker compatible candidates can accumulate chain evidence. Pending continuations must supply their own evidence before extending a confirmed prefix. Finite FFT or clock-window search retains bounded candidates and sufficient statistics. Noise-model scores and search corrections are not calibrated false-alarm probabilities for arbitrary real interference or proofs of LPI. |
| Modem and stream inspection tabs | Console, Modem flow, Transmission layout and Compression / raw bits show one-bit patterns, settling, fixed interval data/HMAC/parity positions and local source-codec capacity. Short text shows its fixed dictionary bits with exact counts and an editable raw-bit preview. Counts derive from the actual stream encoder and fixed geometry. |
| Automatic HF radio-frequency tuning | Not yet implemented. The planned addition would find suitable shortwave ionospheric propagation frequencies as an alternative to ALE/FHSS. Current audio carrier selection and finite receive searches do not perform this RF tuning. |

Acceptance of sensitivity, capacity, RF compliance, adversarial security or
hardware isolation requires an agreed measurement procedure and intended-device
results. Deterministic software loopbacks cannot establish those properties.
