# Implementation coverage

This matrix records version 0.7.2 behavior and its limits. It is not acceptance of
all performance and hardware claims in the original design. Audio peers need
matching waveform settings. Automatic profiles now use binary pattern transport;
larger content retains the compact 0.7 packet codec, and existing keyfiles are unchanged.
[Test execution results](validation.md) distinguish measured results from design
and source-level checks.

| Requirement | Implemented behavior / current boundary |
| --- | --- |
| Portable compiled modem | C++20 CLI and default FLTK GUI share the transfer/streaming service and OpenSSL 3. Optional Rev uses C++23 and the shared controller/bitmap boundary; its Linux software-OpenGL profile is tested. Linux ALSA is dynamically optional; Windows uses WinMM. No Python or Tk runtime dependency. See [Rev boundaries](rev-backend.md); Windows hardware validation remains separate. |
| Offline installation transfer | CMake/CPack collects compiled executables and native libraries. Bundled FLTK, OpenSSL and release C++ runtimes default to static linking. Moving a release needs no interpreter or package download. OS/CPU/glibc compatibility limits are in [offline-installation.md](offline-installation.md). |
| Portable CI binaries | GitHub Actions builds and tests Linux and MSVC Windows archives, with static CRT/OpenSSL, relocation, checksum and GUI checks. Linux CI targets glibc 2.35 and checks downloaded copies on Ubuntu 22.04/24.04, rejecting GTK/GLib dependencies. Hosted results require an actual successful workflow run; local newer-glibc builds do not inherit that baseline. |
| Text, screenshots and files | Text compose and strict UTF-8 clipboard copy; binary file and saved-screenshot attachments. Received text stays in the ticker; only files/screenshots appear in the explicit-save list. No built-in screenshot capture. |
| Interface isolation | PCM or analog audio only, with OS-default device and optional override. No network listener, serial modem substitute, content execution, routing or automatic file opening. Hardware isolation is external. |
| 256 MiB receive content | Bounded RAM cache with ID replacement and eviction. DSP has an independent ceiling, defaulting to 50% available RAM with a 25/50/75% GUI dropdown. It allocates useful bounded sample history, candidate records and receiver workspaces, not the entire selected allowance. Packet scratch has checked content-derived bounds. Neither number is a total process RSS guarantee. |
| Large keyfile and pad | Production 128 MiB random header wraps an authenticated collection of 1..128 named complete five-purpose keysets. GUI opens, generates/saves in the background and shows the loaded file's folder. New files use exclusive creation and select the first named key. Legacy keyfiles load as Default. Optional large pad support remains in CLI. No physical-erasure guarantee. |
| Compose convenience fields | GUI Callsign and Grid seed an editable `CQ CQ CQ DE <callsign> GRID <grid>. Please reply. ` greeting when Message is cleared; absent fields omit their corresponding clause, and both absent omit the greeting. Values are carried only in visible message text. Starting a text transmission clears to the current convenience text and enables Previous message - click to paste for exact message restoration, including its repeatable identifier. Editing the recalled message generates a fresh identifier. |
| Repeatable messages | GUI Repeatable prepends the in-band `REPEATABLE-XXXXXXXX ` marker before the greeting, with eight random uppercase/lowercase consonants (excluding Y/y) or digits. Every message content edit, including insertion, deletion or paste, regenerates the identifier. Repeatable turns off for attachments or payloads over 256 bytes, counting the 20-byte prefix, greeting and UTF-8 bytes. Empty/off convenience fields insert no text or spaces. CLI and packet API retain the integrity-protected repeat flag and incremental-content policy: at most 2 seconds or at most one original byte, excluding fixed training/framing/metadata. No built-in repeater. |
| Short bits and protected packets | Automatic raw bits and text below 16 source UTF-8 bytes add no header, checksum, MAC, FEC or padding. A separate hardware-settling waveform lasts approximately five seconds rounded to the nearest whole payload-symbol duration (ties up), or zero for symbols longer than ten seconds; it supplies no payload bits or acquisition condition. Text of at least 16 bytes and files/screenshots of any size retain the compact packet codec: flags/ULEB128-length/CRC16 bootstrap, metadata, SHA-256 or keyed HMAC, and optional body RS/interleaving. Pattern evidence controls acquisition and burst boundaries; packet integrity controls subsequent packet validation. See [protocol](protocol.md). |
| Protected settling and packets | Pattern transport is the sole waveform; explicit APSK/multi-bit profiles are rejected. The rounded settling prefix mixes Data and every enabled Scrambler/DSSS stream before circular I/Q mapping, in separate preamble counter positions. It does not control acquisition. Packet coding and integrity follow recovered pattern bits. No post-encryption symbol padding exists. |
| Automatic compression | Short pattern text below 16 original bytes always uses exact fixed dictionary bits; common bytes such as `e` use three bits, without byte padding or a compression flag. Packet payloads below 256 bytes use the fixed prefix-code candidate when it saves bytes; longer packets use raw LZMA2 preset 9 extreme. Packet flags/original length select those paths, without a dictionary/codebook identifier. Vendored static liblzma needs no destination packages. |
| Cipher streams | AES-256-CTR with HKDF purpose/epoch separation. Data, DSSS and Scrambler are independent purposes; FHSS is reserved. Private chips consume eight bytes per absolute chip to map variable amplitude and phase, with fixed seek caches. Selected non-tone keys always enable private patterns. Raw paths have no MAC or replay protection; packet HMAC remains downstream. Unix-time anchors approximate absolute time. |
| Tone policy | Tone modes force encryption, Scrambler and DSSS off; the GUI clears and disables key selection and the transfer/CLI/live APIs normalize stale keys away. Tone modes are unencrypted communications or experiment modes, with no LPI claim. The obsolete public audio whitening layer has been removed. |
| Time, key and target search | Receive searches only the selected bandwidth and pattern/tone mode. A separate comma-separated target C/N0 field accepts up to 16 finite values in -200..200 dB-Hz; invalid input resets the whole list to `40`, and equivalent profiles share one search. Loaded keys, whole-second epochs (default ±6 seconds), finite carrier offsets and timing hypotheses are subject to aggregate workspace admission. Resource-limited coverage is reported; unlimited search and nanosecond discipline are not implemented. |
| Transmit policy | One active GUI TX. Six-second cooldown applies to actual encrypted output; simulation and plaintext output have no cooldown. Automatically timed keyed pattern bursts also wait for a fresh local whole-second epoch; explicit timestamps remain caller-controlled. These policies do not coordinate separate processes or hosts sharing a key. |
| Phase and amplitude modulation | Private pattern chips use bounded circular Gaussian-derived I/Q noise with key-dependent amplitude and phase. Public patterns use real +/-1 rows. The two bit alternatives differ in internal transitions. Tone uses two carrier offsets. No APSK constellation lock is used. |
| Automatic weak-signal duration | Bandwidth and target C/N0 choose binary-pattern integration, with at least 64 nominal chips in automatic profiles and an initial modeled 18 dB symbol-energy target. Longer integrations advance the full private stream beyond 16,384 chips. Forced shorter profiles remain selectable but may be marked below the standalone confidence target. No measured sensitivity or false-alarm guarantee follows from this planner. |
| Long-symbol memory behavior | TX generates bounded PCM chunks using fixed seekable code caches. RX normally uses bounded FFT/baseband history; symbols exceeding that workspace can use a scalar correlator with an explicit half-chip clock-start window and finite frequency/rate bank. State scales with that hypothesis count, not airtime. At 1.2 kHz, ±2-second/one-rate coverage uses about 7.13 MiB per epoch/profile; the default ±7-second window uses about 24.53 MiB before wrappers. Multiple rates/epochs increase memory and CPU; live real-time feasibility is not established for large banks. See [measured bounds](pattern-constellation.md#streaming-long-symbol-correlation). |
| Planner and throughput bounds | Automatic transport carries one bit per pattern rather than maximizing APSK density. Capacity optimality, minimum workable pattern length and calibrated weak-signal sensitivity are not established. No LDPC or adaptive equalizer is implemented. Finite local timing adjustments and explicit rate/frequency hypotheses do not provide an unrestricted oscillator tracker. |
| Bandwidth | Nominal 1 Hz..30 MHz planning sets internal `Fs=max(6000,ceil(4B))` and carrier `max(1500,0.75B)`, independently of hardware. The floor represents a usable narrowband audio carrier; nominal symbol timing remains bandwidth-derived. Audio negotiates the selected card's rate and uses bounded band-limited conversion, with stages for large downsampling ratios. Physical passband limits remain; the wider planning range does not supply an SDR backend. Rectangular pulses retain sidelobes without a certified spectral mask. |
| Few-bit status | Pattern transport sends and blindly recovers exact raw bits, including leading zeros and non-byte lengths, without supplied boundaries or bit counts. Three bits occupy three payload symbols plus rounded settling, with no symbol padding. Raw confidence does not authenticate identity or prove a physical long-distance link budget. Legacy aligned APSK/DBPSK status has been removed. |
| Multi-signal reception | Bounded pattern candidates and chains can report bursts within the finite frequency/timing/key/epoch bank. Continuous capture releases old waveform history. No whole-band simultaneous decoder or RF retuning control; admission limits can exclude hypotheses. |
| Provisional text and completed bits | Completed pattern raw bits and dictionary text can be presented and copied without packet validation; their lack of checksum/FEC is explicit. Packet files still require validated parsing. Simulation releases completed received results at its replay deadline, without using prepared message contents as reception. |
| Signal reception quality | Pattern rows show model log evidence separately from measured SNR and packet authentication. Decoded text uses one row; other receptions retain exact bytes/bits. Raw and short dictionary text have no checksum/FEC claim. Validated packets retain encoded-body pre-FEC accuracy. No legacy training-coverage diagnostic is produced. |
| Diagnostics | Continuous sample windows preserve carrier phase; waveform, spectrum and waterfall remain bounded. Pattern clouds show measured differential chip observations; constellation residual does not control acquisition. Observations and overflow are tracked, with input and decoded sources distinguished. Slow-rate formatting remains; overloaded-device performance is not guaranteed. |
| Simulation | Independent free-running receiver processes actual PCM with seeded fractional start timing/carrier phase, AWGN, default 100 ppm relative crystal error and 0.5 degrees/sqrt(second) Wiener phase diffusion. Idle noise continues and TX boundaries do not reset RX. Memory is bounded; work scales with sample count. Presets use -174 dBm/Hz plus 10 dB noise figure, normalized to Fs/2. Ideal-clock overrides retain unsynchronized startup. |
| Simulation presentation | The complete pattern transmission, plots and receptions replay over three wall-clock seconds, normally in 60 compact frames, including rounded settling. Completed text/bits and verified packets appear at the deadline. Queued calls replay consecutively; new TX or Stop interrupts presentation and discards undelivered results while retaining completed receptions. Delayed polls do not extend replay. |
| Replay storage | Skipped-frame points merge within bounded source-specific batches; overflow or points left undelivered at the deadline are reported as omitted. Workspace uses at most DSP budget/8, capped near 1.4 MiB, including roughly 38 KiB of result diagnostics plus plots, points and up to 4096 preview-text bytes per frame. Smaller budgets reduce capacity. Prepared packet content uses the separate content quota. |
| Physical channel effects | Sampled simulation and batch PCM apply startup timing/phase, delay, frequency shift, clock resampling and phase noise. Pattern fits determine acquisition success; finite local timing adjustments or explicit rate hypotheses cover only their implemented range. No continuous carrier-drift tracker, fading/multipath or hardware nonlinearity model. Long integrations can fail with the default crystal error/phase noise even when memory fits. |
| QR Level L | Vendored encoder, UTF-8 ECI, up to 500 Unicode scalars; compose preview and SVG/PBM CLI output. Independent decoding history is recorded in validation results. |
| Pattern/scrambler constellation | Modem flow shows two one-bit codeword rows with duration-weighted distances and energy-normalized timing comparisons. Long symbols show at most a 16,384-chip illustrative prefix. Private illustrations reset to public example keys and epoch, never actual streams. Tone distances are chip-center approximations. No diagram calibrates reception confidence. |
| Pattern acquisition | Soft pattern-versus-noise fits alone admit symbols and refine timing; neither APSK residual, preamble, checksum nor packet validity locks the automatic receiver. Strong individual symbols can establish a burst; weaker compatible candidates can accumulate chain evidence. Pending continuations must supply their own evidence before extending a confirmed prefix. Finite FFT or clock-window search retains bounded candidates and sufficient statistics. Noise-model scores and search corrections are not calibrated false-alarm probabilities for arbitrary real interference. |
| Modem and packet inspection tabs | Console, Modem flow and Transmission layout share settings while reception continues. Views show exact one-bit patterns, separately counted protected settling, raw/short-text encoding and downstream packet coding. No APSK view or post-encryption padding remains. Counts come from actual encoder/estimator; diagrams omit contents and private streams. |
| Explicit exclusions | No asymmetric key exchange, built-in repeater, routable address, rapid Doppler tracking, SDR/FHSS or IC-7100 control. No legal classification claim. |

Acceptance of sensitivity, capacity, RF compliance, adversarial security or
hardware isolation requires an agreed measurement procedure and intended-device
results. Deterministic software loopbacks cannot establish those properties.
