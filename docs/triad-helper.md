# Helper-assisted triad acquisition: retained findings

Current implementation and validation rules are in [Robust architecture](robust-current.md)
and [abbreviated testing](triad-performance.md). This note preserves research
ideas and source-bound evidence, not a second implementation or a recipe to
rerun retired campaigns. Historical results do not qualify changed code.

The retained native composition combines DATA and the complete Helper waveform
before shared propagation. Both therefore experience the selected continuous
oscillator/channel processes, guards and tails. Explicit Helper-off and
effect-off baselines distinguish assistance from a changed test signal.

Frequency assistance can reduce a DATA frequency search while leaving the
original arrival/epoch prior intact. Pilot-to-DATA phase transfer is a separate
claim: frequency-selective transfer, path renewal and auxiliary separation can
make it unresolved even when useful frequency information survives. See the
[stochastic findings](triad-stochastic.md).

Receiver inputs are noisy samples and public keyed alternatives. Simulator
arrival, actual bit, hidden tap values and true frequency must not narrow the
receiver bank. Helper-present/DATA-absent observations are a distinct null from
pure noise. A score improvement is not an operational admission guarantee;
proposal selection and repeated attempts belong in the accounting.

The [extended evidence](validation-data/triad-v3/2026-11-05-helper-extended/README.md)
and [coverage lessons](triad-helper-coverage.md) preserve supported configurations
and failures. The canonical native Generator and complete receiver are integrated
into the GUI; earlier HelperData/raw/finite-bank wrappers and campaign drivers
are retired. These historical Helper results do not qualify current GUI
integration or complete-message reception; see [current validation](validation.md).
