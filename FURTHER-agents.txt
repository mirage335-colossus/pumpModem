E. REQUIRE ASTRA TO CHOOSE AND SPECIFY A PRACTICAL SHARED REPRESENTATION

The following are design obligations and concrete candidate approaches, not
claims that every proposed interface already exists. Astra must inspect the
current implementations, select the strongest applicable route, derive its
identities, and turn it into ordered edit cards. It may choose a better route
with evidence. Do not simply tell Sol to "use FFTs" or "improve caching."

E1. Establish a common immutable numerical event description

Define or reuse a descriptor sufficient for numerical work without mutating a
Hypothesis or PatternCode shared with another worker. It must identify:
- Capture owner/revision/continuity generation; original physical sample range,
  original processing fence and timestamp/correction map.
- Key/profile namespace, schedule identity, stream epoch/canonical phase,
  independent bit-candidate addresses, source-symbol index and carry ownership.
- Exact clock/rate and frequency family; physical carrier restart/origin and
  source affine mapping on each active piece. Store precise coordinates in the
  existing integer/long-double representation; do not use floats for epochs.
- Admitted timing outputs/ranges and any fractional residues; explicit valid
  sample mask, schedule/FHSS gain, finite pulse support, clipping/limiter state.
- Guard partitions: current/adjacent symbol, source chip, quarter/drift section,
  differential window and outer-presence pulse basis. Include partial end chips.
- Arithmetic/template policy, approximation/error model, immutable template
  family identity, workspace reservation and cancellation generation.

Prefer adapting existing Catalog::Family, original boundary partition, prepared
events and shared capture types over creating duplicate calendars. Document
which fields are necessary for identity and which are merely diagnostics.
No pointer address alone may stand in for content/revision identity across
reuse, eviction, cancellation or reconstruction. Sensitive template values must
retain the current lifetime/cleansing policy; never log keys or plaintext PCM.

E2. Separate preparation, numerical contraction and ordered commit

Specify a three-stage execution pipeline, including exact signatures or proposed
types, ownership and error paths in Astra's plan:
1. On the coordinator: enumerate the next bounded due family from immutable
   catalog/physical fences; reserve all input/template/guard/worker/output bytes;
   acquire leases; prepare immutable event descriptors. Do not advance trials,
   processed frontiers or acceptance state yet.
2. Workers: compute reusable projections and candidate sufficient statistics
   using private execution scratch and PatternCode instances or immutable
   already-generated rows. No shared LRU mutation, owner creation, room_for,
   whole-bank loan changes, pending publication or complete() in workers.
3. On the coordinator after join: visit results in the original chronological
   logical order, apply the correct current trial charge/threshold, refine
   unsupported/error-sensitive results, commit complete/timing/pending/absence
   state and publish on the next poll. Advance the processing journal only over
   committed fences. Keep successful earlier commits on cancellation and resume
   uncommitted work exactly once without double-counting observations or trials.

Make numerical results threshold-independent where practical. If a screen needs
a threshold, bound it against all possible thresholds during the ordered batch
or defer the decision until commit. Do not use a later threshold to retroactively
reject an earlier weak-chain candidate. Clarify short-chain retain thresholds,
reliable-bit thresholds and ordinary final admission separately.

The current lazy early return cannot be fixed safely just by moving normal
prepare_workers above it. Identify precisely which numerical resources can be
factored into a lazy execution context, how each is charged and how contexts are
borrowed across banks. Existing normal dense and raw paths remain controls.
Do not confuse parallel candidate replay with shared execution: thread-level
parallelism alone can hide wall latency while aggregate CPU remains wasteful.

E3. Multi-dwell FFT processing with correct physical carrier time

Investigate processing several active dwells/cycles in a bounded numerical
batch, not necessarily an entire long symbol and not one FFT per0.4s dwell.
For a fixed family, write the actual statistic before transforming it. A useful
real-input form is:
  b = sum over observed n of y[n] * v[n]
  G = sum over observed n of v[n] v[n]^T
  E = sum over observed n of y[n]^2
  N = the actual admitted sample/degrees count
where v contains the actual real I/Q template basis after physical carrier,
source mapping, pulse shaping, gain and limiting. Signs/conjugation/normalization
must follow existing Fit and Gram code, not this schematic notation.
Keep bit0/bit1 statistics independent. Guard-specific sufficient statistics
have additional partitions; whole-fit agreement alone is insufficient.

On each active interval, source position is piecewise affine in physical time.
Derive whether timing candidates share the same input/gain/mapping family and
differ only by a template shift. Where they do, correlation outputs can replace
independent candidate reconstructions. At changes of mask, source ownership,
clock slope, pulse support, fractional residue or limiter behavior, partition
or use an explicit edge fallback. Count the edge work in complete cost.

Two candidate organizations to compare, with measured crossovers:
(a) Active physical tiles with overlap-save/add or partitioned convolutions.
    Transform each reusable input/projection plane once per tile/frequency group;
    transform source/template/Gram planes once per true identity; produce many
    timing outputs and accumulate them over dwells into bounded candidate state.
    Preserve physical offsets for phase and partial source-chip ownership.
(b) A compact active-source representation after appropriate physical-time
    mixing, with a segment table carrying original physical timestamps, mapping,
    weights, gap phase, source coordinate and boundary/covariance information.
    Use larger source-domain FFTs only where the mapping makes this legitimate.
    If input resampling is introduced, explicitly derive its noise correlation,
    effective observations/Gram and template interpolation; it is not an exact
    refactor merely because its output looks contiguous.

Chopping null PCM out and applying an ordinary FFT is NOT generally exact.
For physical frequency f, each captured segment retains its exp(-i2pi*f*t)
phase. Source time pauses but t does not. A per-segment phase factor is enough
only after proving the within-segment rate/clock mapping and candidate family.
Residual frequency uncertainty still accumulates over physical aperture; an
error delta-f incurs phase about2pi*delta-f*Tphysical. Compact storage does not
erase that need. Explain how a coarse physical DDC, fine-family recurrence or
frequency transform supplies the segment phases without repeating all raw mixing.

Do not allocate a symbol-long physical FFT mostly containing nulls. Bound tile
length, overlap, transformed planes, active pieces and retained outputs by the
configured workspace. A logical symbol lasting hours must be processed in
bounded pieces. Tile size should respond to density, output count, reuse and
latency; narrow timing need not mean direct execution if a small FFT is cheaper.

Explicitly inspect the existing point FFT's8 input planes/16 output planes,
streaming accumulation and paired template cache before reinventing them. Ask
whether expensive guard replay can consume its prepared events/statistics;
whether it currently recomputes a family per lane/fence; whether multiple
frequencies or epochs can borrow input planes; and whether its prefix update
causes repeated transforms. Keep valid implementation rather than start anew.
Its current StreamingEngine::append already permits a disjoint template interval
to cross several physical dwells; it does not remove physical gaps. Thus "make
the FFT multi-dwell" is not sufficient diagnosis by itself. Inspect the caller's
actual tiling, padding, reuse and replay. The current reservation contains
T*(10*sizeof(complex<Tscalar>)+32*sizeof(complex<double>)) plus outputs and
overhead: about592 bytes per transform point for float, before other pools.
For131072 points that term alone is about74MiB. Native float operands therefore
do not make unlimited simultaneous full-Gram transforms cheap. Evaluate streamed
planes, frequency/timing tiling and valid reuse using complete memory traffic
and synchronization cost; do not discard required Gram planes to save bytes.

E4. Integrate energy, real Gram and guards instead of accelerating only dots

For each original detector component, provide an exact additive-state table:
input data, template identity, sufficient statistics, boundary events, final
nonlinear function, numerical requirements and conditions for sharing. Include:
- Real I/Q correlation vector and complete2x2 Gram, including cross term and
  rank/conditioning. Do not silently assume circular complex noise/orthogonality.
- Raw observation energy/count and projected/noise energy without counting nulls
  or artificially zero-filled samples. Masks can differ at timing boundaries.
- Per-source-chip projections/energies/ranks and structured colored excess.
- Quarter/drift section active fits, explained sums, largest section, boundary
  ranks and phase-cell coverage. A missing quarter cannot become zero evidence
  that is classified as a fully observed absent symbol.
- Differential-window state and expected counts; preserve all current windows.
- DSSS outer-presence/public-pulse guard state, finite support and complete ring
  of prior pulse contributions, with current/carry symbol ownership distinct.
- Partial final chips, fractional sample starts, limiter transitions, FHSS ramps,
  schedule ramps and overlap across the payload/cover boundary.
- Weak-chain state, timing-neighbor comparisons, admission trials, pending
  identity and observed-absence counters, which generally remain ordered state.

Final scores are nonlinear, but their input sufficient statistics can often be
accumulated over pieces. Determine which guard statistics can be reconstructed
from shared prefix/moment/convolution planes and which need bounded original
edge replay. Do not simply certify a high raw score and replay the entire symbol
again for every candidate. Measure how much Original replay remains afterward.

For a lower-cost Default approximation, define the approximation explicitly,
which guards it changes numerically, its range/conditioning checks and fallback.
Use current authorized interpolation and measured accuracy constraints, not an
accidental requirement that every Default intermediate be bit-identical FP64.
Conversely, a loose interval bound that admits everything is not useful screening.
If certificate construction is more expensive than direct family computation,
select direct shared computation for that geometry. If strong interference
forces most lanes to refine, make the fallback family-wise and bounded rather
than a catastrophic return to independent full-symbol replay.

E5. Frequency-family work must include the full detector

Within a common clock/source/mask family, reuse baseband projections across
frequency alternatives with the existing recurrence/fusion/transform machinery
where appropriate. Include frequency-dependent real Gram and guard products,
not just the signal dot. Derive coarse/fine split, phase origin, recurrence
restart interval, residual error bounds, exact endpoints and clock coupling.
Any Taylor/chord approximation needs complete accumulated error/rank bounds;
the admissible physical aperture can be much longer than a numerical tile.

Do not prune finer frequencies required by scheduled physical aperture. Measure
the actual added count separately from cost per hypothesis. Audit duplicated
equal-rate pairs, canonical phase multiplicity and common anchor/source rows.
Share exact identical data without merging distinct trials or private identities.
Quantify whether a2D timing/frequency transform, polyphase grouping or direct
vectorized contraction is cheaper for the actual family sizes, including all
normalization/guard planes and batch preparation. Do not infer crossover from
one large sparse FFT,43x dot kernel or theoretical instruction throughput.

E6. Cross-rolling-bank sharing and bounded batching

Use stable immutable physical tiles as the unit of key-independent validation,
mixing and moments when banks request overlapping history. Key-dependent maps
and templates remain separate. A bank's relative sample origin must not defeat
reuse when the absolute captured interval and processing recipe are identical.
Identity must include capture revision/continuity, absolute range, input rate,
carrier frequency/recurrence convention, clock transform, precision, gain/mask
dependencies and any interpolation revision. Cache only statistics actually
independent of key/epoch/candidate; unweighted physical projections may be shared
more broadly than candidate-specific gain-weighted moments.

Align compatible consumers to common tiles without delaying accepted-bit
publication. Establish whether retaining projections, original PCM, source rows
or partially reduced fits is cheapest for the next consumers. Exact source
sample caches need both independent bit values and precise crypto/pulse identity.
Whole-symbol DSSS permutation reuse can be exact, but must not imply reuse of
private source samples at different cryptographic addresses.

Allow batches to span multiple cycles within a byte/age/latency budget. Trigger
computation on sufficient reusable work, approaching memory/age limits, due
publication/completion events or cancellation. Do not wait for an entire long
symbol, another message, or a fixed large batch merely to get a favorable FFT.
Define fairness across keys/epochs/profiles and pressure-triggered progress.
The producer must remain independent; a blocking ingest call cannot throttle
test input and disguise an unsustainable queue.

Document mandatory storage versus optional acceleration, peak old+new buffers
during growth, active leases/pins, parallel scratch, transforms, metadata,
guard archives, deferred diagnostics and queued input. Optional-cache eviction
must not discard required observations or cause OOM before cold admission.
Add reasoned fallback when reuse is unavailable; count fallback storms and
whether one large bank starves later banks. Preserve future-consumer proofs.

E7. Productive arithmetic, not labels

Default automatic chooses measured fastest eligible execution. FP32 minimum
forbids narrower operands but may use necessary FP64 state. FP64 force uses
original templates, unquantized FP64 search operands and no approximate template
interpolation; exact reuse and efficient FFT/vector algorithms remain allowed.
Algorithm, arithmetic and reuse policy must remain independent.

Create a current stage table for input, mixing, transforms, spectral products,
source coefficients, interpolation, dots, Gram/energy, reductions, guards,
scoring, timestamps and refinement. Record storage, multiplication and
accumulation separately. A float FFT followed by FP64 original replay is partial
coverage. Do not present an environment name or dropdown as executed precision.

Use native FP32 buffers/plans/products where total cost and accuracy support them.
Retain double/compensated or wider accumulation and sensitive subtraction/rank
tests where needed. Inspect generated instructions and runtime dispatch for the
executed hot code; preserve portable binaries and do not globally require AVX2.
Existing point FFT's compensated FP64 accumulation and real Gram policy provide
a concrete starting point. Measure conversions, packing and plan setup too.

Revisit narrower integer/mixed arithmetic only if the changed batching creates
enough long regular work to overcome preparation. Preserve I/Q, scales, zero
points, saturation/overflow bounds and refinement. Current tiny pieces and
weighted moment widths are valid scope-specific obstacles, not universal bans.
Quantitatively bound likely total gains using current fractions. Do not spend
the pass emulating FP8/INT8 or repeating already-slower fixed-bank prototypes.

E8. Consolidate selection only after an integrated gain

Inventory experimental environment controls and precedence. Specify a small
internal strategy decision that chooses dense, implicit direct, tiled family,
point/guard or exact fallback from actual geometry and charged resources. Keep
diagnostic overrides for reproducing evidence. Production Auto must select the
demonstrated route in the acceptance fixtures; an opt-in-only success does not
finish the product. FP32 minimum should share the same supported efficient
algorithm when precision permits, rather than accidentally fall back because
an experimental entry point checks onlydefault_mode.

Do not delete old references/failing fixtures or collapse independent numerical
policies merely to make code uniform. Remove redundant new machinery only after
its consumers, identities and evidence have been reconciled. The plan should
reduce accidental policy interactions, not add another mutually preempted flag.
