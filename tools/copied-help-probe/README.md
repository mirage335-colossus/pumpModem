# Copied Help causal capture

This opt-in diagnostic applies four pinned postimages to an isolated, unchanged
source `37f4315c553b9fc3807f2f173d9a0fae3f239ebc`. It preserves the original
GUI assertions and deadlines. It does not qualify a release or recover the old
failed input.

The manual `copied-help-causal-diagnostic` SDK application scope builds with the
existing published SDK and runs at most two independent synthetic smokes,
stopping on the first failure. It retains the original application exit, package,
synthetic key, full trace, transmit/GUI boundaries, terminal poll history,
candidate decisions and received f32 input. Recording arms before the final
binary edit. Hot recording uses bounded memory; output is flushed after workers
join. Missing data, caps, errors or incomplete closure are diagnostic failures.

The actual post-boundary transmission ID joins `source_context.transmission_id`
to a stable source-quota/generation/revision tuple. Target acceptance requires
continuous PCM from sample zero, successful feed commits, and a prior successful
constructor record for every admitted or resident receiver. A seal's aggregate
configuration flag alone is insufficient. Candidate identities use the same
source quota and each receiver's `point_consumer`.

Generated source progress is distinct from transmitted progress. Complex
projected bytes and complete Session state are not retained. Replaying the
captured f32 with the recorded mixer/configuration requires independent output
equality checks before claiming faithful replay or attributing a cause. No
matched trace-overhead or general performance claim follows from a capture.
