# Evaluation plan for a standalone experiment

This plan is for a later native experiment under `_appraisal/algorithms-matrixModem/`. The figures below set bounded research stages and illustrate exposure requirements. They are neither deployment requirements nor completed tests. Start with the [analytical limits](information-limits.md), [channel evidence](hf-channels.md) and [receiver design](receiver-architecture.md).

## Declare the operating envelope before comparing waveforms

Record a case as the combination of a transmit profile, equipment and path, receiver search contract, and an observable result requirement. Include all of the following.

| Field group | Declare and preserve |
| --- | --- |
| Link | Service/band and RF reference, antenna-plus-feed gains/losses, noise/reference plane, path type, circuit distance and direction, geomagnetic latitude along the route, time/season, known weather regime, path strength and uncertainty. Use conducted 2 and 100 mW as endpoints when useful. Include 150, 165 and 180 dB *assumed* total path loss as link-budget anchors; capture received power and avoid counting antenna losses twice. |
| Transmitter | Measured or modeled SSB audio passband, total allocated width, effective emission, edges and hop transitions, alphabet and symbol/guard durations, peak and mean power, Helper power and timing, fixed code and interleaver. Compare actual total radiated time and energy for the same payload and reliability. Include a fixed-frequency control and one frequency-diversity route. |
| Path state | Per-tap Doppler center and width convention, delay and gain, frequency/time correlations, onset and duration of an outage, trajectory/innovation seeds and episode identities. Keep clock, RF offset, audio rate and atmospheric common drift separate. Include true noise-only, co-channel line, impulse, wrong key, wrong ordinal, collision and clipped/missing input controls. |
| Receiver | Public search intervals and their source, admission and completed hypotheses, selected numerical route, null/label decision calibration, Helper available/off/failure, resource limits, post-quantization score representation, and causal information available at each decision. Distinguish known epoch/ordinal, configured uncertainty, and unqualified acquisition. |
| Public result | Bit/erasure sequence, wrong-label and false DATA rate, quiet/ambiguous sequence, complete exact delivery, incorrect delivery, false end, acquisition/reacquisition and completion time, censored result and reason. A complete receiver's processing time includes continuous input through the scored quiet intervals. Ordinary records also need elapsed airtime, energy per delivered bit and missed deadlines. |

Compare warm steady service and startup separately. One message opportunity is a valid success unit only against its original payload and a deadline. An example near-match on a synthetic waveform is a mechanism check. A delivered message with incorrect bits, an erroneously early quiet completion or a resource/timeout stop cannot be counted as a success. Report lower-percentile rates or higher-percentile durations by path class, along with conditional results and outcome intervals. Set application target reliability with scope and confidence before selection. A “typical” profile can then designate an evidence-backed envelope, with margin against the relevant harder cases, instead of choosing a nominal parameter where half the messages fail.

## Cheap to expensive, with explicit stop conditions

| Stage | Work and test inputs | Decision the evidence can support |
| --- | --- | --- |
| 0. Semantics and math | Independent signed arithmetic/check vectors, complex sign convention, −8 negation and maximum dot/square/carry edges, deterministic window/offset/guard boundaries, FSK ambiguity, sample-quantizer mapping and invalid rows. Check the Gaussian ROC and a noisy two-tap channel against the analytical formulas, outside the operating precision path. Confirm target-specific instruction feasibility if the required toolchain/device is already available. | Stop the affected path on any exact arithmetic, observability, known-signal ROC, or unsupported-route discrepancy. Retain paths with the original precision contract and explicit signed-range semantics. |
| 1. Detector screen | Three reference conditions first: AWGN with oscillator offset, F.1487 mid-latitude moderate (1 ms/0.5 Hz), and high-latitude disturbed (7 ms/30 Hz). Compare whole-aperture, segmented and a single fixed low-rank detector; binary and 16-ary at the same useful payload and total energy. Run up to 3 power levels around one predicted transition and 16 independently seeded, paired episodes per level for each of these initial strata. Run same-geometry noise-only controls and false-end outage cases. | Rank and identify first divergence, with no qualification claim. Retain a route if physical evidence survives independent holdout; withdraw comparisons invalidated by differing bandwidth, energy, state or searched hypotheses. A plausible regime reversal merits keeping both routes. |
| 2. Channel and decoder holdouts | Add distinct delay-heavy NVIS (7 ms/1 Hz), low-latitude disturbed (6 ms/10 Hz), an independent source-informed extreme auroral return with wider composite spread, heavy-tailed common residual and selective gains, burst interference, model-independent onset, correlated fade and true outage. Freeze at most two promising routes and one comparator before fresh holdouts. Use a small fresh paired batch of 32 episodes per chosen stratum initially; extend once to 96 total only if a declared consequential uncertainty can be resolved. Cover short alarms and at least one longer bounded payload with controlled interior erasures. Keep measured replays episode-separated; more placements in one capture are clustered. | Accept a conditional trend only when paired endpoints and uncertainty support it. If sample budget is insufficient, report an inconclusive result or a bracket. No pooling a sparse severe stratum into easy-case successes. Correctly marking an outage incomplete is a separate result from delivering an intact message. |
| 3. Native service and simulation | Compare scalar exact baseline, optimized CPU, and available GPU mechanisms under matched candidate geometry, scheduling and precision receipts. Start with the deterministic checks and short steady-backlog intervals. Use the same compiled receiver for rendered and live-style inputs. Include successful DATA, noise-only, unsuccessful/stale Helper, full drift and time grids, and ordered quiet completion. Use sustained-enough abbreviated intervals to expose queue growth, throughput and thermal/runtime variability, with a separately timed repeated run for verification. | Compare complete useful service, peak bounded memory and latency. An arithmetic kernel trace or offline parallel ensemble is not a one-stream capacity result. A route qualifies only on the actual device and verified arithmetic. |
| 4. Calibrated noise and replay | Run holdouts of calibrated received noise and, where provenance and bandwidth permit, independent time-varying channel replays plus separately injected DATA. Compare observer and intended receiver at matched receive power/reference plane, observation budgets and allowed false alarms. Record whether the instrument measured full complex channel response, a single carrier, band power or decoded reports. | Claim only tested capture, equipment, observer and conditioned channel coverage. Report H₀ exposure limits alongside detections and censoring. |

These sample budgets illustrate screening economics. For a prespecified independent binomial trial with zero failures, a one-sided 95% upper bound is `1 − 0.05^(1/n)`. At `n=16, 32, 96` the limits are 17.1%, 8.9% and 3.1%. A zero-failure result needs 299 independent whole-message trials even to put that upper bound at 1%. Adjacent symbols in one fade and repeated slices of one recorded episode do not provide that independence. Use an exact binomial interval for genuinely independent trials and paired exact or episode-cluster uncertainty for matched comparisons. Preallocate error across planned stages or use a valid time-uniform procedure when using intermediate looks for inference. Quote the predeclared outcome and all retests so exploratory selection remains distinguishable from the final held-out claim.

At 6.25 eligible slots/s there are 22,500 opportunities per hour. Under uniform calibration a per-slot false DATA target of `1/22500` gives one expected false DATA per hour before clustering or a multi-slot admission rule. After zero errors the same 95% upper bound requires about 67,403 independent slots to demonstrate that per-slot value. For a 1% bound on any event per hour by a union bound, the per-slot target is `0.01/22500`, and the independent empirical requirement rises to roughly 6.74 million. A small demonstration should therefore report a tractable false-alarm bracket and use an analytical null under justified assumptions, with independent ambient-tail checks. Never multiply two per-slot quiet-error rates unless independence is justified. [Observer exposure and calibration](observer-and-interference.md).

## Two comparisons that decide most of the architecture

### Equal waveform and null decisions

Freeze a finite fixture with known public clock, 160 ms nominal symbols, one symbol guard, a deliberately imperfect passband, all label frequencies and explicit physical quiet slots. Include one near-threshold tone and two separated observations for timing ambiguity. Use deterministic scalar signed-digit projections to compare direct dense, reusable channelizer plus narrow follow-up, and positional updates. The observed input/validity span and candidate coordinate map must hash to the same identities across equal-detector routes. Wide or floating analysis may compute an independent oracle offline. Compare score differences caused by actual quantized templates and post-processing, then report the resulting held-out decision and operational errors. A no-difference result on aligned FFT bins does not cover non-grid timing/frequency, delayed tails, sparse support or near-null cancellation.

- Predicted pattern if dense projections are the bottleneck and reusable factoring helps: repeated windows/offset alternatives share products; complete slot service improves after including gathers, norms, masks, reductions and commit. A larger best-case TOPS value without increased completed search capacity is insufficient.
- Predicted pattern if computation is concentrated in nonlinear bookkeeping/absence/codec: the projected kernel speeds up while service and simulation turnaround stay near the previous bottleneck, or backlog moves to transfers/epilogue. Use complete stage receipts before tuning hardware-specific tile shapes.
- Predicted pattern if the main limit is physical: a perfect template or oracle timing/channel gives a clear gap to the realizable receiver, or even the oracle misses the fixed energy/deadline target. In the first case distinguish missing phase knowledge, acquisition, code and quantization. In the second case revisit the link requirement on these assumptions before spending on throughput.

### Equal complete service, then routine versus difficult workload

Independently report `wall time by stage`, `completed hypotheses/s`, unique reusable projections/s, elapsed radio seconds processed per wall second, p95/p99 ready-to-commit delay, input backlog slope, resident/pinned/scratch bytes, and matched observation coverage. Report device identity, compiler/backend, execution instruction, profiler mechanism, clocks and effective work. Distinguish `GPU busy` from tensor pipeline issue/active metrics and dense-equivalent executed operations. Count zeros, padded rows/columns, rescoring and test-only oracle work separately. Test a narrow feasible real-time workload, a broad quiet/failure backlog, a same-stream adverse reconstruction and a batched simulation workload. The last measures simulation throughput, separately from one-stream latency.

Compare the arithmetic-permitted CPU and iGPU paths as actual implementations. For NVIDIA, verify compiled architecture, inspect instructions, exact integer results and actual device execution before profiling. Ada and Blackwell require their own receipts. Include comparison to full RTX PRO 6000 Blackwell when available and authorized under the project hardware policy. Keep software thread ceiling `W=2H`, actual OS/thread allocation, device occupancy and useful service separate. Record explicit fallback and memory admission, including competing activity for unified RAM. Retain only compact source-bound findings and unresolved indispensable evidence.
